# 카드정산 (CardFit)

연말정산 카드 소득공제를 모르는 사람에게 "신용카드와 체크카드를 각각 얼마나 써야 하는지"를
눈금 하나로 보여주는 계산기.

**라이브:** [https://cardfit-two.vercel.app/](https://cardfit-two.vercel.app/)

세금을 최대한 아끼게 해주는 서비스가 아니라, **언제 신경 쓸 필요가 없는지까지 정확히 알려주는**
서비스다. 문턱을 못 넘긴 사용자에게는 "아무 카드나 쓰세요"라고 말한다.

## 실행

```bash
npm install
npm run dev      # 개발 서버
npm run test     # 계산 로직 테스트 25개
npm run build    # dist/ 생성
```

## 배포 (Vercel)

현재 배포 주소: [https://cardfit-two.vercel.app/](https://cardfit-two.vercel.app/)

깃허브에 올린 뒤 Vercel에서 저장소를 선택하면 끝이다. Vite 프로젝트로 자동 인식된다.

- Framework Preset: Vite
- Build Command: `npm run build`
- Output Directory: `dist`

환경변수나 서버가 필요 없다. 계산이 전부 브라우저에서 끝나고, 사용자의 급여나 소비 금액이
어디로도 전송되지 않는다. 소득 정보를 다루는 서비스라 이 구조를 의도적으로 선택했다.

## 구조

```
src/
  lib/deduction.ts       소득공제 계산. 순수 함수, UI 의존성 없음
  lib/deduction.test.ts  테스트 25개 (경계값·회귀·법 개정 대응)
  lib/tax.ts             한계세율 추정 (근로소득공제 → 과세표준 → 세율 구간)
  lib/netPay.ts          실수령액 추정 (4대보험 + 소득세 → 월 실수령)
  lib/format.ts          금액 표시
  components/Gauge.tsx   소비 구간 눈금자
  App.tsx                화면
```

계산과 화면을 분리한 이유는 세법이 바뀌면 `lib/`만 고치면 되게 하기 위해서다.
`deduction.ts`의 모든 상수에는 근거 조문 번호가 주석으로 달려 있다.

## 계산 근거

조세특례제한법 제126조의2. 조문 최종 개정은 2025년 12월 23일(법률 제21223호)이고,
현행 법률 제21549호(2026년 4월 21일 시행)에서 이 조문은 개정되지 않았다.

핵심 규칙은 세 가지다.

1. 총급여의 25%를 넘게 쓴 금액부터 공제가 시작된다 (제1항)
2. 신용카드 15%, 체크카드·현금영수증 30% (제2항 제4호·제5호)
3. 한도는 총급여 7천만원 이하 300만원, 초과 250만원. 자녀가 있으면 상향 (제10항)

계산 과정에서 확인한 성질 하나: **신용카드 사용액이 문턱 이하이면 신용/체크를 어떻게 나눠
써도 공제액이 같다.** 그러므로 "문턱까지는 신용카드 먼저"라는 통설의 근거는 세금이 아니라
카드 혜택이다. 화면에서도 그렇게 설명한다.

## 검증한 것과 안 한 것

검증함

- 계산 산식과 차감 순서를 국가법령정보센터 조문 원문과 직접 대조
- 무작위 30만 건을 정수 산술 기준값과 대조해 오차 0 확인
  (부동소수점 버전에서는 1,024건에서 1원이 어긋났다)
- 경계값 테스트: 문턱 ±1원, 한도 정확 도달, 총급여 7천만원 ±1원

아직 안 함 — 배포 전에 해야 할 일

- [ ] **국세청 홈택스 연말정산 자동계산과 실제 대조.** 산식은 조문과 맞췄지만 국세청 구현과
      1:1로 맞는지는 확인 전이다. 케이스 5~10개를 넣어보고 결과를 기록할 것
- [ ] **법률 제21223호 부칙 확인.** 자녀 수 한도 가산이 어느 귀속연도부터인지 미확정이다.
      2026년 귀속으로 추정되나 확정 전까지 자녀 입력은 참고용으로만 볼 것
- [ ] **4대보험 요율 갱신.** `tax.ts`의 `SOCIAL_INSURANCE_RATE`와 `netPay.ts`의
      `INSURANCE_RATES`가 추정값이다. 환급액과 실수령액 표시가 이 값에 걸려 있으므로
      최신 고시 요율로 바꿀 것
- [ ] **실수령액 대조.** `netPay.ts`는 1년치 세금을 12로 나눈 값이라 실제 월급 명세서와
      다르다. 실제 급여는 근로소득 간이세액표로 원천징수한다. 시중 연봉계산기 몇 개와
      대조해 오차 범위를 확인하고, 화면 문구를 그에 맞게 조정할 것

## 아직 없는 기능

- 근로소득 간이세액표 기반의 정확한 월 원천징수액 (지금은 연 세액을 12로 나눈 추정)
- 전통시장 · 대중교통 · 도서공연영화 · 체육시설 (별도 추가 한도가 붙는다)
- 배우자·부양가족 카드 사용액 몰아주기
- 공제 제외 항목 자동 분리 (지금은 사용자가 뺀 금액을 넣는다고 가정한다)

특별 카테고리를 추가할 때는 제126조의2 제2항 제6호 **다목**을 반드시 함께 구현해야 한다.
지금 코드는 차감 분기를 두 개만 다루는데, 특별 카테고리가 없어서 세 번째 분기에 도달할 수
없기 때문이다. 카테고리를 넣는 순간 조용히 틀리기 시작하고 기존 테스트로는 안 잡힌다.
`deduction.ts` 헤더 주석에 같은 내용을 남겨뒀다.
